# 新電力向け 需給管理プロトタイプ（OpenSTEF）

翌日の30分×48コマについて、需要予測 → 調達計画 → JEPXスポット入札量 → インバランス評価 → 計画CSV出力 までを一通り行う検証用のプロトタイプです。需要予測エンジンに [OpenSTEF](https://github.com/OpenSTEF/openstef) v4 を使っています。

同梱のデータは**合成したサンプル**（東京エリア、高圧業務用中心、最大需要およそ5万kW）です。実データに差し替えて使うことを前提にしています。

## できること

| 業務 | 内容 | 実装 |
|---|---|---|
| 需要予測 | 前日9:00時点で翌日48コマをP10/P50/P90で予測。日本の祝日・座標を反映 | `jukyu/forecast.py` |
| 調達計画 | 相対契約（昼夜ブロック）、太陽光（日射量から推計）、残りをJEPXスポットで調達 | `jukyu/planning.py` |
| JEPX入札 | 不足分を買入札、余剰分を売入札。基準分位点・上限価格を設定可能 | `jukyu/planning.py` |
| インバランス評価 | 実績との差、不足/余剰量、簡易単価での精算額と損失 | `jukyu/planning.py` |
| 出力 | 需給計画CSV、JEPX入札一覧CSV、インバランス評価CSV、HTMLダッシュボード | `jukyu/export.py`, `jukyu/dashboard.py` |

## セットアップ

Python 3.12 以上が必要です（OpenSTEF v4 の要件）。

```bash
python3.12 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 実行

```bash
# 1. サンプルデータを作る（実データがあれば不要）
python -m jukyu.sample_data data/sample_30min.csv

# 2. 翌日計画＋過去14日の検証
python run_daily.py --date 2026-10-05 --backtest-days 14

# 3. ダッシュボードを作る（ブラウザで開く）
python -m jukyu.dashboard output/results.json output/dashboard.html
```

GitHub Pages では `docs/index.html` を公開しています（サンプルデータの結果）。更新するときは `python -m jukyu.dashboard output/results.json docs/index.html` で作り直してコミットします。実データの結果は `docs/` に置かないでください。

1日分の学習・予測はCPUで7秒前後です。`--model gblinear` で別モデルも試せます（サンプルでは xgboost の方が祝日に強く、精度が高い結果でした）。

## Claude Code で使う

このフォルダで `claude` を起動すると、`CLAUDE.md` の約束（単位・時刻・リーク禁止・自動入札禁止など）を前提に作業します。次のコマンドが使えます。

| コマンド | 内容 |
|---|---|
| `/daily-plan [日付]` | 翌日（または指定日）の48コマ計画を作り、要注意コマと出力ファイルを報告 |
| `/backtest [日付] [日数] [モデル...]` | 過去期間で検証し、モデルや入札基準ごとの誤差・インバランス損失を比較 |
| `/import-data <ファイル...>` | 送配電の30分値・気象・JEPX価格のファイルを入力形式に変換して検証 |

ロジックを変更したあとは「jukyu-reviewer でレビューして」と頼むと、単位の混在や時刻の取り違え、データのリークを重点的に確認します。よく使うコマンド（テスト、計画作成）は `.claude/settings.json` で許可済みなので、毎回の確認なしで実行されます。

## 実データへの差し替え

`data/` に次の列を持つ30分間隔のCSVを置き、`--data` で指定します。

| 列 | 内容 | 入手先の例 |
|---|---|---|
| `timestamp` | 日時（タイムゾーン付き、例 `2026-10-01 00:00:00+09:00`）。コマの開始時刻 | — |
| `load` | 自社BGの需要実績（kW、30分平均） | 一般送配電事業者から提供される30分値（kWh×2でkW） |
| `temperature` | 気温（℃） | 気象庁の過去データ、気象予報API |
| `relative_humidity` | 相対湿度（%） | 同上 |
| `windspeed` | 風速（m/s） | 同上 |
| `pressure` | 気圧（hPa） | 同上 |
| `radiation` | 全天日射量（W/m²） | 同上 |
| `jepx_spot` | JEPXスポットのエリアプライス（円/kWh） | JEPXの公開データ |

注意点:

- **気象は「予報値」を使ってください。** 学習・予測のどちらも、その時点で手に入る予報で揃えると、本番と同じ条件で精度を測れます。サンプルでは実績値を使っているため、精度が実運用より良く出ます。
- 需要実績が予測時点（前日9:00）までにどこまで届くかは契約・エリアによって違います。遅れがある場合は `forecast.py` の `issue_time` 以降を欠損にしている処理を、実際の到着時刻に合わせて調整してください。
- 電源構成（相対契約・太陽光の容量）や入札方針は `jukyu/config.py` で変更します。

## 制度面で未実装の部分（本番化で必要）

このプロトタイプは計算の流れを確認するためのものです。実運用には次の作業が必要です。

1. **広域機関への計画提出**：出力CSVは社内確認用の簡易様式です。広域機関システムの所定様式への変換と提出処理が必要です。また、計画値同時同量のため需要計画と調達計画を一致させる必要があります（本プロトタイプは入札量を100kW単位に丸めているため、コマごとに数十kWhの計画差が出ます）。
2. **JEPXの入札**：入札量の最小単位や価格の刻みは取引規程を確認して `BID_ROUND_KW` などを合わせてください。入札は人が確認してから行う運用を推奨します。
3. **インバランス料金**：本プロトタイプは「スポット価格×係数」の簡易モデルです。実際の精算はインバランス料金の算定式（補正インバランス料金算定インデックス等）に従います。
4. **時間前市場・当日の再計画**：ゲートクローズ（実需給の1時間前）までの再予測と時間前市場での調整は未実装です。
5. **予測の分位点の較正**：サンプルではP10–P90の幅が狭めに出ています。OpenSTEFの `quantile_calibration` チュートリアルの手法で較正すると、入札基準分位点の設定がより意味を持ちます。

## ファイル構成

```
run_daily.py               日次実行（予測→計画→評価→出力）
jukyu/config.py            BG・電源構成・入札方針の設定
jukyu/sample_data.py       サンプルデータ生成
jukyu/forecast.py          OpenSTEFによる48コマ予測
jukyu/planning.py          調達計画・JEPX入札量・インバランス評価
jukyu/export.py            CSV出力
jukyu/dashboard.py         HTMLダッシュボード生成
jukyu/dashboard_template.html
```

## ライセンス

このプロトタイプのコードは自由に改変して使えます。OpenSTEF は MPL-2.0 です（OpenSTEF自体のファイルを改変して配布する場合はそのファイルの公開が必要）。
